# Документация: дашборд баркодов

## Руководство пользователя

1. Откройте фронтенд-приложение и перейдите на главный экран дашборда.
2. В блоке "Типы" выберите формат баркода: EAN-13, EAN-8, Code 128, QR или Data Matrix.
3. Заполните название виджета, источник данных и владельца. Эти поля помогают клиентам понимать, кто отвечает за поток данных.
4. Введите тестовое значение баркода. Интерфейс сразу покажет ошибку, если значение не подходит под выбранный формат.
5. Выберите статус: "Активен", "Черновик" или "Пауза".
6. Нажмите "Добавить в дашборд". Новый виджет появится в списке и станет доступен в превью.
7. Для просмотра деталей нажмите на любой добавленный виджет в нижнем списке.

## Описание функционала

- Поддержка нескольких типов баркодов: EAN-13, EAN-8, Code 128, QR и Data Matrix.
- Подсказки по каждому формату: назначение, допустимый формат и пример значения.
- Валидация тестового значения до добавления виджета в дашборд.
- Карточки аналитики с количеством всех, активных и черновых баркодов.
- Превью выбранного баркода с базовой визуализацией, источником, владельцем и статусом.
- Список добавленных виджетов для быстрого переключения между сценариями.

## Алгоритм работы

1. Пользователь выбирает тип баркода.
2. Система подставляет шаблон, пример значения и набор ожидаемых аналитических метрик.
3. Пользователь вводит рабочие параметры: название, источник, владельца, статус и пример кода.
4. Клиентская валидация проверяет формат:
   - EAN-13: ровно 13 цифр.
   - EAN-8: ровно 8 цифр.
   - Code 128: до 48 печатных латинских символов.
   - QR: до 160 символов.
   - Data Matrix: до 120 символов.
5. После успешной проверки виджет добавляется в начало списка дашборда.
6. Выбранный виджет отображается в панели превью и может быть использован как основа для будущей интеграции с API аналитики.

## Запуск

```bash
cd frontend
npm install
npm run dev
```

Для проверки логики:

```bash
npm test
```
