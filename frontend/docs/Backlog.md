## План тестирования WB API для оперативной сводки

Цель: проверить, какие методы дают данные за текущую неделю и текущий день, потому что финансовые отчёты WB обычно становятся доступны с задержкой и не закрывают оперативную аналитику.

| Блок | Метод-кандидат | Что проверить |
|------|----------------|---------------|
| Баланс | `GET /api/v1/account/balance` | Доступность по финансовому токену, формат ответа, частота обновления |
| Заказы | методы Statistics / Marketplace для orders | Есть ли данные за сегодня и текущую неделю, какие статусы доступны |
| Продажи / выкупы | методы Statistics для sales | Отличие продаж от выкупов, наличие srid / nmID для сопоставления |
| Отказы / возвраты | методы Statistics / Reports с признаком операции | Где появляются возвраты за текущий период и с какой задержкой |
| Финансовые отчёты | `sales-reports` и `acquiring` | Подтвердить задержку по текущей неделе и использовать как закрывающий финансовый источник |

Протокол проверки:

1. Проверять методы только с реальным WB-токеном продавца с правами на Контент, Маркетплейс, Статистику, Аналитику и Финансы.
2. Сохранять сырой ответ каждого метода в отдельный лог без токена и персональных данных.
3. Сравнивать периоды: сегодня, текущая неделя, прошлая неделя.
4. Фиксировать `status`, лимиты, поля идентификации товара (`nmID`, `chrtID`, `barcode`, `vendorCode`, `srid`) и задержку появления данных.
5. После проверки обновить этот backlog точными методами для заказов, выкупов, отказов и возвратов.
